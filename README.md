# Browser Panel

Веб-панель на твоём VPS (`https://твой-домен/browser/`) для запуска изолированных браузерных сессий и автоматических сценариев.

- **Каждая сессия — чистый браузер.** Под каждую сессию запускается отдельный процесс Chromium с новым временным профилем. При закрытии или перезапуске он уничтожается целиком: cookies, кэш, localStorage, история — ничего не переносится.
- **Конструктор сценариев:** «начать сессию → перейти по ссылке → курсор в координаты → клик ЛКМ → ввести текст → … → перезапустить сессию».
- **Живой экран:** видно, что происходит в браузере; координаты выбираются кликом по экрану, действия можно записывать прямо в сценарий.
- **Пул прокси** с распределением по сессиям и сменой IP для мобильных прокси.
- **Расписание** («каждые N минут»), повторы, история запусков со скриншотами.
- **API** для своего iOS-приложения или скриптов.

## Как работает прокси на сессию

Прокси добавляются во вкладке «Прокси». В шаге «Начать сессию» выбирается режим:

| Режим | Что происходит |
|---|---|
| Без прокси | Сессия идёт с IP сервера. |
| Из пула по кругу | Берётся следующий **свободный** прокси: 1-я сессия → прокси A, 2-я → B, 3-я → C, 4-я → снова A и т.д. |
| Конкретный прокси | Всегда этот прокси. |

**Прокси ограничены, и это нормально:**

- У каждого прокси есть настройка «Сессий на один прокси» (по умолчанию 1). Если у тебя 3 прокси и лимит 1, одновременно работают максимум 3 сессии с прокси. Сессия, которой не хватило прокси, завершится с ошибкой «Все прокси заняты».
- Сессии, которые идут **по очереди**, используют прокси повторно. Когда сессия закрывается, прокси освобождается и достаётся следующей.
- **Мобильные / ротируемые прокси.** Если провайдер даёт ссылку смены IP (например, `https://provider/changeip?key=…`), укажи её у прокси. В шаге «Перезапустить сессию» поставь галочку «Сменить IP»: панель откроет эту ссылку, подождёт 5 секунд и запустит новый браузер **на том же прокси**, но уже с новым IP. Так одного мобильного прокси хватает на сколько угодно последовательных сессий.
- «Перезапустить сессию» без смены IP в режиме «Из пула» берёт следующий свободный прокси из пула.
- Кнопка «Проверить» показывает внешний IP прокси, «Сменить IP» вручную дёргает ссылку ротации.

Форматы строк: `http://user:pass@host:port`, `host:port:user:pass`, `user:pass@host:port`, `host:port`, `socks5://host:port`. SOCKS5 с логином и паролем Chromium не поддерживает — для таких бери http-вариант у провайдера.

## Подписки (VPN / Happ)

Во вкладке «Прокси» → «Подписки» вставь ссылку подписки. Панель скачает её, разберёт на локации (с флагами и странами) и поднимет для каждой локальный прокси. Дальше в шаге «Начать сессию» (и «Перезапустить сессию») можно выбрать:

| Вариант | Что произойдёт |
|---|---|
| Случайная локация из подписок | Каждая новая сессия получает случайный сервер, подряд один и тот же не берётся. |
| Случайная из «название подписки» | То же, но только из этой подписки. |
| 🇩🇪 DE: случайная | Случайный сервер из выбранной страны. |
| Конкретная локация | Всегда этот сервер. |

**«Перезапустить сессию» с режимом «Как было» и случайной локацией берёт новую случайную локацию** — удобно для сценариев «каждый заход с нового IP».

Как это устроено: Chromium не умеет VLESS/VMess/Trojan, поэтому рядом работает xray-core. У каждой локации свой SOCKS-порт на `127.0.0.1` (наружу не открыт), Chromium ходит через него как через обычный прокси. Поддерживаются VLESS (в том числе Reality, WS, gRPC, xhttp), VMess, Trojan, Shadowsocks. Hysteria2, TUIC и WireGuard пропускаются — панель покажет, сколько серверов пропущено.

- Подписки обновляются сами раз в `SUB_REFRESH_HOURS` часов, кнопка «Обновить» — вручную. Если сервер подписки недоступен, старые локации остаются рабочими.
- Если xray не принял какой-то сервер, он помечается «не работает» с причиной, остальные работают.
- «Проверить» у локации открывает внешний IP через неё — так видно, что сервер жив.
- Если подписка зашифрована Happ (`happ://crypt…`), панель не сможет её прочитать — попроси у провайдера обычную ссылку (для v2rayN/v2rayNG).
- Ссылка подписки — это секрет. Она хранится только в файле `subscriptions.json` в томе `panel-data` на твоём сервере (права 600), в репозиторий не попадает. Не вставляй её в публичные места.
- При добавлении или удалении подписки xray перезапускается, поэтому активные сессии на этот момент теряют соединение. Меняй подписки, когда сценарии не идут.

## Шаги сценария

| Шаг | Параметры |
|---|---|
| Начать сессию | прокси |
| Перезапустить сессию | прокси (или «как было»), сменить IP |
| Закрыть сессию | — |
| Перейти по ссылке | URL (только http/https) |
| Курсор в координаты | X, Y, время движения (курсор едет плавно) |
| Клик мышью | X, Y (пусто — там, где курсор), ЛКМ / ПКМ / колесо, двойной |
| Ввести текст | посимвольно с паузой между символами |
| Вставить текст | целиком, как из буфера |
| Нажать клавишу | Enter, Tab, Backspace, Control+A … |
| Прокрутка | по вертикали / горизонтали |
| Пауза | мс ± случайный разброс |
| Ждать элемент / Клик по элементу | CSS-селектор |
| Обновить страницу, Скриншот | — |

Координаты считаются в окне браузера фиксированного размера (по умолчанию 1280×800, задаётся в `.env`). Поэтому координаты, выбранные на экране в панели, совпадают с координатами при запуске.

**Как удобнее собирать сценарий:**

1. Справа нажми «Тестовая сессия» — появится экран браузера.
2. Введи адрес в поле под экраном и нажми «Перейти». Кликай по экрану, вводи текст — всё уходит в настоящий браузер.
3. Включи «записывать в сценарий», и каждое действие добавится шагом в конец сценария.
4. Кнопка 🎯 у шага → клик по экрану подставит координаты в этот шаг. Кнопка ▶ у шага выполнит его в тестовой сессии.
5. «Сохранить» → «Запустить». Ход выполнения виден в логе справа, история — во вкладке «Запуски».

Тестовые сессии, которыми не пользуются 15 минут, закрываются сами (`MANUAL_IDLE_MIN`).

## Установка на VPS

Нужны Docker с плагином compose и nginx с настроенным доменом и https.

```bash
git clone <этот репозиторий> browser-panel && cd browser-panel
cp .env.example .env
nano .env                  # обязательно поменяй ADMIN_PASSWORD
docker compose up -d --build
```

Потом добавь в конфиг nginx твоего домена блок из [`deploy/nginx-browser.conf`](deploy/nginx-browser.conf) (внутрь существующего `server { … }`) и выполни:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Панель откроется на `https://твой-домен/browser/`. Остальной сайт на домене не затрагивается.

Обновление: `git pull && docker compose up -d --build`. Сценарии и прокси хранятся в docker-томе `panel-data` и при пересборке не теряются.

**Ресурсы:** каждая одновременная сессия — это отдельный Chromium, примерно 200–400 МБ RAM. `MAX_SESSIONS` ставь по памяти сервера: на 2 ГБ — 2–3, на 4 ГБ — 5–6.

Без Docker: Node.js 20+, xray-core в `PATH` (или `XRAY_PATH`), затем `npm ci && npx playwright install --with-deps chromium && ADMIN_PASSWORD=… node src/server.js`.

## Настройки `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ADMIN_PASSWORD` | — | Пароль входа, минимум 4 символа. |
| `API_TOKEN` | пусто | Токен для API (`Authorization: Bearer …`). Пусто — API работает только по cookie после входа. |
| `BASE_PATH` | `/browser` | Префикс пути на домене. |
| `PORT` | `3100` | Порт (слушается только на 127.0.0.1). |
| `MAX_SESSIONS` | `3` | Максимум одновременных браузеров. |
| `VIEWPORT_WIDTH` / `VIEWPORT_HEIGHT` | `1280` / `800` | Размер окна браузера. |
| `SUB_REFRESH_HOURS` | `6` | Как часто обновлять подписки, 0 — только вручную. |
| `XRAY_PATH` | `xray` | Путь к xray (в Docker-образе уже установлен). |
| `COOKIE_SECURE` | `1` | Ставь `0`, только если заходишь по http без https. |
| `MANUAL_IDLE_MIN` | `15` | Через сколько минут закрывать забытую тестовую сессию. |

## API (для iOS-приложения)

Все пути относительно `https://домен/browser/api`. Авторизация: заголовок `Authorization: Bearer <API_TOKEN>` или cookie после `POST /login {"password": "…"}`. Ответы — JSON, ошибки — `{"error": "…"}`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/config` | Описание всех шагов (тип, поля), размер окна. |
| GET / POST | `/scenarios` | Список / создать `{name, steps, repeat, intervalMin, scheduleEnabled}`. |
| GET / PUT / DELETE | `/scenarios/:id` | Прочитать / изменить / удалить. |
| POST | `/scenarios/:id/run` | Запустить, вернёт запуск. |
| GET | `/runs`, `/runs/:id` | История; у `/runs/:id` есть `logs`, `screenshots`, `currentStep`, `sessionId`. |
| POST | `/runs/:id/stop` | Остановить. |
| GET | `/runs/:id/shots/:file` | Скриншот запуска (PNG). |
| GET / POST | `/sessions` | Активные сессии / открыть тестовую `{proxy}`. |
| GET | `/sessions/:id/screenshot` | Текущий экран (JPEG) — для живого просмотра. |
| POST | `/sessions/:id/step` | Выполнить один шаг `{step: {type, params}}`. |
| DELETE | `/sessions/:id` | Закрыть. |
| GET / POST | `/subscriptions` | Список с локациями и статусом xray / добавить `{url, name}`. |
| POST / DELETE | `/subscriptions/:id/refresh`, `/subscriptions/:id` | Обновить / удалить. |
| GET / POST | `/proxies` | Список / добавить `{text: "строки прокси", rotateUrl, maxSessions}`. |
| PUT / DELETE | `/proxies/:id` | Изменить `{label, rotateUrl, maxSessions}` / удалить. |
| POST | `/proxies/:id/check`, `/proxies/:id/rotate` | Узнать внешний IP / сменить IP. |

Пример шага: `{"type": "click", "params": {"x": 640, "y": 400, "button": "left"}}`.

Панель уже адаптирована под телефон. На iPhone: Safari → «Поделиться» → «На экран Домой» — откроется как приложение без адресной строки.

## Безопасность

- Порт приложения слушается только на `127.0.0.1`, снаружи доступ идёт через nginx.
- Вход по паролю: после 5 неудачных попыток IP блокируется на 15 минут; после 20 неудачных попыток суммарно со всех IP вход закрывается на час. Cookie `HttpOnly`, `SameSite=Strict`.
- Шаг «Перейти по ссылке» разрешает только `http(s)://`, поэтому прочитать файлы сервера через `file://` нельзя.
- История запусков и скриншоты хранятся в памяти и очищаются при перезапуске контейнера.
